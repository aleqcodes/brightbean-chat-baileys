A condition document cannot express the first — the closest it gets is "somebody who now has VIP", which fires when any tag at all is added to a VIP — so the id filter is its own control. The condition bar is `contacts/_filter_bar.html` unchanged, rendered from the same `filter_config` payload the CRM's list page uses.
